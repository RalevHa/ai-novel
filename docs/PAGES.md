# หน้าเว็บและ flow การทำงาน (web)

แต่ละหน้าอยู่ที่ `web/src/pages/` เส้นทางทั้งหมดกำหนดใน `web/src/router.ts` การเรียก API ทั้งหมดผ่าน `client` (Eden) ใน `web/src/api.ts` ชื่อเส้นทาง API ด้านล่างเขียนแบบ `GET /api/...` ตรงกับ `server/src/index.ts` และ `server/src/site.ts` สรุปฟีเจอร์ในภาพรวมดูที่ `FEATURES.md`

## ภาพรวม

### สิทธิ์เข้าหน้า (`router.beforeEach`)
| meta | ใครเข้าได้ | ถ้าไม่ผ่าน |
|---|---|---|
| (ไม่มี) | ทุกคน | เข้าได้ |
| `user: true` | ผู้ที่ล็อกอินแล้ว | ไป `/login?next=<หน้าเดิม>` |
| `staff: true` | นักเขียนและแอดมิน | ไป `/login?next=…` |
| `admin: true` | แอดมินเท่านั้น | ไป `/login?next=…` (ถ้าอยู่ในมุมมองจำลอง ไป `/story`) |

- สิทธิ์ที่ใช้คือ `auth.isAdmin` / `auth.canWrite` (บทบาทที่ใช้ตอนนี้ ซึ่งเปลี่ยนตามมุมมองจำลอง) ไม่ใช่ `auth.user.role` ดู `web/src/viewAs.ts`
- เปิดเว็บครั้งแรกที่ `/` ตอนล็อกอินอยู่ จะไป `/story` เลย (กดโลโก้ภายหลังยังเห็นหน้าแรก) คนล็อกอินแล้วเข้า `/login` หรือ `/register` จะถูกส่งไป `/story`
- เซิร์ฟเวอร์ตรวจสิทธิ์ซ้ำเสมอ (`adminOnly`, `staffOnly`, `userOnly` ใน `server/src/auth.ts`) หน้าเว็บกันเพื่อความสะดวกเท่านั้น

### Store และตัวช่วยที่ใช้ร่วมกัน
| ไฟล์ | ทำอะไร |
|---|---|
| `stores/auth.ts` | ผู้ใช้ปัจจุบัน `load()` ตอนเปิดเว็บ (`GET /api/auth/me`), `login`, `register`, `verify`, `logout`; `role` / `isAdmin` / `canWrite` / `previewing` / `canRemove` |
| `stores/bookmarks.ts` | ชั้นหนังสือ (เรื่องที่ติดตาม) `toggle(id)` พลิกสถานะทันทีแล้วย้อนกลับถ้าเซิร์ฟเวอร์ปฏิเสธ |
| `stores/notifications.ts` | จำนวนแจ้งเตือนที่ยังไม่อ่านบนกระดิ่ง ถามใหม่ทุก 1 นาทีขณะแท็บเปิด |
| `readState.ts` | ตำแหน่งที่อ่านค้างและตอนที่อ่านจบ: เก็บใน localStorage เสมอ ล็อกอินแล้วซิงก์ขึ้นบัญชีด้วย (`PUT /api/me/progress/:id`, `POST /api/me/reads/:id`) และนับยอดอ่านวันละครั้งต่อตอน |
| `prefs.ts` | ตั้งค่าการอ่าน (ธีม ฟอนต์ ขนาด ฯลฯ) ซิงก์ข้ามอุปกรณ์ (`GET/PUT /api/me/prefs`) |
| `confirm.ts` | `ask()` dialog ยืนยันกลางตัวเดียว ใช้ก่อนลบ/ทำสิ่งที่ย้อนไม่ได้ |
| `toast.ts` | `toast()` / `toastError()` ข้อความแจ้งผลมุมล่าง |

### Flow หลัก
```
สมัคร:   /register → POST /auth/register → /verify?email → กรอกรหัส 6 หลัก → POST /auth/verify (ได้ session) → /story
เข้าระบบ: /login → POST /auth/login → /story  (รหัสถูกแต่ยังไม่ยืนยันอีเมล → ได้ needsVerify → /verify)
ลืมรหัส:  /forgot → POST /auth/forgot → กรอกรหัส + รหัสใหม่ → POST /auth/reset → /login
อ่าน:     /story → /story/:id → /story/:id/read/:no  (ขอตอนถัดไปด้วยปัดซ้าย/ขวา ปุ่มลูกศร หรือการ์ดตอนถัดไป)
เขียน:    /admin/stories → สร้างเรื่อง → /admin/stories/:id → ให้ AI เขียนเป็นฉบับร่าง → แก้ไข → เผยแพร่/ตั้งเวลา
```

## หน้าสำหรับทุกคน

### `/` หน้าแรก — `LandingPage.vue`
- **ทำอะไร:** แนะนำเว็บ เรื่องเด่น วิธีที่เรื่องถูกสร้าง จุดเด่น และทางลัดไปแนว
- **ข้อมูล:** `GET /api/stories` (รายการเดียวกับชั้นหนังสือ ไม่มีข้อมูลแยก)
- **ฟังก์ชันสำคัญ:** `featured` เลือก 3 เรื่องที่คะแนนดีที่สุด (ถ้ามีรีวิวพอ) ไม่งั้นเรื่องที่อัปเดตล่าสุด, `motion()` แอนิเมชันเลื่อน (GSAP) เฉพาะจอ ≥768px และไม่ตั้งค่าลดการเคลื่อนไหว, `useResume` การ์ด "อ่านต่อ"

### `/story` ชั้นหนังสือ — `StoryListPage.vue`
- **ทำอะไร:** ค้นหา กรองตามแนว เรียงลำดับ และกรอง "เฉพาะที่ติดตาม"
- **ข้อมูล:** `GET /api/stories` ครั้งเดียว ค้นหา/เรียง/กรองทำในเบราว์เซอร์ (ยังไม่แบ่งหน้า); ล็อกอินแล้วโหลดชั้นหนังสือจาก `stores/bookmarks`
- **Flow:** พารามิเตอร์ `?q=&genre=&sort=` ตั้งค่าเริ่มต้นได้ (ใช้จากไอคอนค้นหาที่หัวเว็บและชิปแนวหน้าแรก) `?search` โฟกัสช่องค้นหา; ลำดับที่เลือกจำใน localStorage (`homeSort`); `shelf()` ใน `shelf.ts` ทำกรอง+เรียง

### `/story/:id` หน้าเรื่อง — `StoryPage.vue`
- **ทำอะไร:** ปก เรื่องย่อ ตัวละคร สารบัญ รีวิว ปุ่มติดตาม อ่านต่อ ดาวน์โหลด EPUB คัดลอกลิงก์ RSS
- **ข้อมูล:** `GET /api/stories/:id`, ตอนที่อ่านแล้ว (`readState.reads`), ตำแหน่งอ่านค้าง (`GET /api/me/progress`)
- **ฟังก์ชัน:** `follow()` ไม่ล็อกอินพาไป login (`next` กลับหน้านี้); กำลังติดตามอยู่ → ถาม `ask()` ก่อนเลิกติดตาม; `jump()` ไปตอนตามเลข; `flip()` สลับเรียงใหม่→เก่า; ตัวสารบัญแบ่งหน้าละ 50 ตอน; แถบ "อ่านต่อ" ล่างจอบนมือถือโผล่เมื่อปุ่มหลักเลื่อนพ้นจอ
- รีวิวและการตอบกลับอยู่ใน `components/ReviewSection.vue` (ดูหัวข้อชุมชนด้านล่าง)

### `/story/:id/read/:no` หน้าอ่าน — `ReadPage.vue`
- **ทำอะไร:** แสดงเนื้อหาตอน พร้อมตั้งค่าการอ่าน เลือกตอน ฟังเสียงอ่าน ถูกใจ บุ๊กมาร์ก และความคิดเห็น (ในแผ่นที่เปิดทับหน้า เพื่อไม่ขยับตำแหน่งที่อ่าน)
- **ข้อมูล:** `GET /api/stories/:id/chapters/:no` + `GET /api/stories/:id` (รายการตอนสำหรับก่อนหน้า/ถัดไป) + `GET .../likes` + (ล็อกอิน) `GET /api/me/chapter-bookmarks/:id`
- **Flow เปิดตอน** (watch บน `id`/`no`): โหลดตอน → เก็บ `last:<id>` และ `lastRead` ใน localStorage → `startReading()` ถามตำแหน่งที่บันทึก (`getPos`) ถ้ามีและยังไม่จบจะเลื่อนกลับไปที่นั่นพร้อมข้อความ "อ่านต่อจากที่ค้าง" (ไม่ทำถ้ามาจากแจ้งเตือนที่ตั้ง `?comments=1`) → เริ่มติดตามการเลื่อน → นับยอดอ่าน (`countView`)
- **ความคืบหน้า:** วัดเทียบกับจุดที่ส่วนความคิดเห็นเริ่ม (`readHeight`) ไม่ใช่ความสูงทั้งหน้า เปิดความคิดเห็นแล้วเปอร์เซ็นต์ต้องไม่เปลี่ยน; ถึง `READ_AT` (90%) หรือเห็นบรรทัดสุดท้ายแล้ว → `finish()` ทำเครื่องหมายอ่านจบ (`markRead`, `countFinish`); กด "ตอนถัดไป" ก็นับว่าอ่านจบ; บันทึกตำแหน่งเป็นช่วง ๆ และตอนซ่อนแท็บ/ปิดหน้า (`flush`)
- **โหมดโฟกัส:** `setChrome()` ซ่อนหัวเว็บและแถบเครื่องมือตอนเลื่อนลง แสดงตอนเลื่อนขึ้น (กติกาใน `reader.ts: chromeHidden`)
- **ท่าทาง:** ปัดซ้าย/ขวาเปลี่ยนตอน แตะกลางจอสลับแถบ (`onTouchStart/End`, `swipeDir`, `isCenterTap`); คีย์บอร์ด ←/→ เปลี่ยนตอน
- **ปุ่มที่ต้องล็อกอิน:** `bookmark()` และ `like()` พลิกสถานะทันทีแล้วย้อนถ้าล้มเหลว; ไม่ล็อกอินพาไป login พร้อม `next`
- **เสียงอ่าน:** `listen()` ใช้เสียงของเบราว์เซอร์ (`tts.ts`) อ่านจบตอนแล้วไปตอนถัดไปต่อ

### `/author/:id` โปรไฟล์ผู้แต่ง — `AuthorPage.vue`
- **ข้อมูล:** `GET /api/authors/:id` ผู้อ่านทั่วไปที่ไม่มีเรื่องจะได้ 404 (ไม่เปิดโปรไฟล์ผู้อ่าน)
- เจ้าของโปรไฟล์เห็นปุ่ม "แก้ไขโปรไฟล์" ไป `/profile`

### `/guide` `/about` `/contact` `/terms` `/privacy` — `InfoPage.vue`
- หน้าเดียวรับ `slug` ทั้ง 5 หน้า ข้อความมาจาก `GET /api/pages/:slug` (เวอร์ชันที่แอดมินแก้ หรือข้อความตั้งต้นใน `server/src/pageDefaults.ts`) เป็น Markdown แปลงด้วย `infoDoc.renderDoc` (ไม่แสดง HTML ดิบหรือรูป)
- ลิงก์ที่ขึ้นต้น `/` ในเนื้อหาเปลี่ยนหน้าแบบ SPA (`onClick`) วันที่ปรับปรุงแสดงเฉพาะข้อกำหนดและนโยบาย

### หน้าบัญชี (ทุกคนที่ยังไม่ล็อกอิน)
| เส้นทาง | ไฟล์ | Flow |
|---|---|---|
| `/login` | `LoginPage` | `auth.login` → ไป `?next` หรือ `/story`; ถ้าเซิร์ฟเวอร์ตอบ `needsVerify` ไป `/verify?email=` |
| `/register` | `RegisterPage` | ต้องติ๊กยอมรับข้อกำหนด/นโยบาย → `auth.register` (ส่งรหัสทางอีเมล ยังไม่มี session) → `/verify?email=` |
| `/verify` | `VerifyEmailPage` | ไม่มี `?email` ย้อนไป `/register`; กรอกรหัส 6 หลัก → `auth.verify` → `/story`; ขอรหัสใหม่ได้นาทีละครั้ง (`resend`, นับถอยหลัง 60 วินาทีตามเซิร์ฟเวอร์) |
| `/forgot` | `ForgotPasswordPage` | ขั้น 1 `send()` ขอรหัส (ไม่บอกว่ามีบัญชีหรือไม่); ขั้น 2 `reset()` รหัส+รหัสผ่านใหม่ → `/login` |
| (ไม่พบ) | `NotFoundPage` | หน้า 404 |

## หน้าสำหรับผู้ที่ล็อกอิน (`user: true`)

### `/following` เรื่องที่ติดตาม — `FollowingPage.vue`
- **ข้อมูล:** `GET /api/me/following` (พร้อมจำนวนตอนที่อ่านแล้ว/ทั้งหมด)
- **ฟังก์ชัน:** กรอง (ทั้งหมด / มีตอนยังไม่อ่าน / อ่านครบ) และเรียง (ติดตามล่าสุด / อัปเดตล่าสุด / ยังไม่อ่านมาก); `unfollow(ids)` ถามด้วย `ask()` แล้วเลิกติดตามทีละเรื่อง (ใช้ `marks.toggle`) ถ้าบางเรื่องล้มเหลวจะแจ้งครั้งเดียว; โหมด "เลือกหลายเรื่อง" ติ๊กแล้วเลิกติดตามพร้อมกัน

### `/bookmarks` ตอนที่บุ๊กมาร์ก — `BookmarksPage.vue`
- **ข้อมูล:** `GET /api/me/chapter-bookmarks` (ตอนที่ผู้อ่านยังเห็นไม่ได้จะหายไป)
- **ฟังก์ชัน:** `remove()` เอาออกทีละตอนหรือหลายตอนหรือทั้งหมด หลัง dialog ยืนยัน (`DELETE /api/me/chapter-bookmarks/:id/:no`)

### `/history` ประวัติการอ่าน — `HistoryPage.vue`
- **ข้อมูล:** `GET /api/stories` + `GET /api/me/progress` นำมาประกอบ (เรื่องที่ไม่เผยแพร่แล้วไม่แสดง) เรียงใหม่สุดก่อน
- **ฟังก์ชัน:** `forget()` ลบเรื่องที่เลือกหรือทั้งหมดหลัง dialog (`DELETE /api/me/progress[/:id]`) และล้างค่า "อ่านล่าสุด" ใน localStorage ที่ตรงกันด้วย เพื่อไม่ให้การ์ด "อ่านต่อ" ดึงเรื่องกลับมา ตอนที่ทำเครื่องหมายอ่านจบไม่ถูกลบ

### `/notifications` แจ้งเตือน — `NotificationsPage.vue`
- **ข้อมูล:** `GET /api/me/notifications` (คำนวณสด ได้แก่ ตอบกลับ โหวตขึ้น และตอนใหม่ของเรื่องที่ติดตาม)
- **Flow:** โหลดรายการ → จุด "ใหม่" ยังโชว์ตลอดการเข้าครั้งนี้ → เรียก `POST /api/me/notifications/read` แล้วตั้ง `bell.unread = 0`

### `/profile` โปรไฟล์ของฉัน — `ProfilePage.vue`
- **แก้โปรไฟล์/รหัสผ่าน:** `PATCH /api/me/profile`; เปลี่ยนรหัสผ่านทำให้อุปกรณ์อื่นหลุด
- **เปลี่ยนอีเมล:** `sendEmailCode` (`POST /api/me/email` ต้องใส่รหัสผ่านปัจจุบัน ส่งรหัสไปอีเมลใหม่) → `confirmEmail` (`POST /api/me/email/confirm`) อีเมลเปลี่ยนเมื่อกรอกรหัสถูกเท่านั้น
- **ลบบัญชี** (ไม่แสดงสำหรับแอดมิน): `closed` → `password` (`POST /api/me/delete` ส่งรหัสไปอีเมล) → กรอกรหัส 6 หลัก `confirmDelete` (`POST /api/me/delete/confirm`) ลบถาวร นักเขียนที่ยังมีเรื่องต้องลบเรื่องก่อน
- **คีย์ AI (นักเขียนและแอดมิน):** `saveKey` (`PUT /api/me/ai-key` ระบบตรวจกับ OpenRouter ก่อนบันทึก), `removeKey` (`DELETE` หลัง `ask()`) เซิร์ฟเวอร์ไม่ส่งคีย์กลับ ส่งแค่ว่าตั้งแล้วกับ 4 ตัวท้าย

## ชุมชนผู้อ่าน (ส่วนประกอบในหน้าเรื่องและหน้าอ่าน)

### ความคิดเห็นรายตอน — `CommentSection.vue` + `CommentItem.vue`
- โหลดตามหน้า เรียงได้; ส่งความคิดเห็น/ตอบกลับ (คำตอบเรียงเป็นแถวเดียวใต้ความคิดเห็นหลัก ตอบคำตอบของคนอื่นก็ไปอยู่ใต้ความคิดเห็นหลักเดียวกัน), โหวตขึ้น/ลง (ห้ามโหวตของตัวเอง), แก้ไขของตัวเอง, รายงาน (ของคนอื่น)
- ลบ: `CommentItem` ส่ง `remove` → `CommentSection.remove()` ถาม `ask()` → `DELETE /api/comments/:id` (ลบได้: เจ้าของ แอดมิน และผู้แต่งเรื่อง)
- รายงาน: `Modal` พร้อมเหตุผล (ไม่บังคับ) → `POST /api/comments/:id/report` คนเขียนไม่รู้ว่าใครรายงาน

### รีวิวเรื่อง — `ReviewSection.vue`
- หนึ่งคนหนึ่งรีวิว (แก้ไขได้) ดาว 1–5 + ข้อความ; ผู้แต่งรีวิวเรื่องตัวเองไม่ได้; `PUT /api/stories/:id/reviews`
- โหวตว่ารีวิวมีประโยชน์ ตอบกลับรีวิว (ลบได้โดยเจ้าของ แอดมิน หรือผู้แต่งเรื่อง) การลบรีวิว/ตอบกลับถาม `ask()` ก่อน

## หน้าจัดการ (`/admin/*`, เลย์เอาต์แถบข้างฝั่งแอดมิน)
`areaName` เป็น "ผู้ดูแลระบบ" หรือ "นักเขียน" ตามบทบาท เมนูข้างของนักเขียนมีแค่ "นิยาย"

### `/admin/stories` จัดการนิยาย — `AdminStories.vue` (นักเขียน+แอดมิน)
- **ข้อมูล:** `GET /api/admin/stories?page&size&q` (นักเขียนเห็นเฉพาะเรื่องของตัวเอง ตัดสินที่เซิร์ฟเวอร์)
- **ฟังก์ชัน:** ค้นหาแบบหน่วง 300 มิลลิวินาที (กลับหน้า 1 ก่อนโหลด); `create()` → `POST /api/admin/stories` แล้วเข้า `/admin/stories/:id`; เมนูต่อแถว: `toggle()` เผยแพร่/ซ่อนเรื่อง, ไปจัดการ, ลบเรื่อง (Modal ยืนยัน)

### `/admin/stories/:id` จัดการเรื่องและตอน — `AdminStory.vue` (นักเขียนเจ้าของเรื่อง+แอดมิน)
แท็บ: ตอน / ตัวละคร (`CharactersPanel`) / ตั้งค่าเรื่อง (ฟอร์มเรื่อง `StoryForm` และปก `CoverUploader`)
- **เขียนตอนด้วย AI:** `generate()` วน `generateOne()` สตรีมจาก `POST /api/admin/stories/:id/generate` มาใส่ `out` สดๆ; `fromOutline` + `count` (1/2/3/5) เขียนตามแผนต่อเนื่อง; หยุดทันทีถ้าข้อความมีเครื่องหมาย `⚠️` (โมเดลวนหรือสตรีมขาด) เซิร์ฟเวอร์เก็บเป็นฉบับร่างที่ยังไม่เผยแพร่ และสรุปตอนให้ทีหลังเอง (หน้าเว็บรีเฟรชซ้ำหลัง 30 วินาที); ออกจากหน้าระหว่างเขียนต้องผ่าน `ask()` (`onBeforeRouteLeave`)
- **แก้ไขตอน:** `openEdit()` ดึงเนื้อหาเต็ม (รายการไม่มีเนื้อหา) → dialog แท็บ เนื้อหา / สรุป / เขียนใหม่ / ตรวจความต่อเนื่อง / ประวัติ; `saveEdit()` ส่งเฉพาะกำหนดเวลาที่เปลี่ยน (มีเวลา = เผยแพร่ตอนนั้น, ล้างเวลา = กลับเป็นฉบับร่าง); `closeEdit()` ถาม `ask()` ถ้ามีการแก้ที่ยังไม่บันทึก
- **เขียนใหม่ด้วยโมเดลอื่น:** `rewrite()` สตรีมจาก `POST /api/admin/chapters/:id/rewrite` ได้ตัวอย่าง; `applyRewrite()` ใส่ลงตัวแก้ไขเท่านั้น ไม่บันทึกเอง
- **สรุปตอน:** `summarizeEdit()` บันทึกข้อความก่อนแล้วสั่งสรุป; `summarizeMissing()` สรุปตอนที่ยังไม่มีทีละตอน หยุดที่ความผิดพลาดแรก (กันเผาโควตาเมื่อคีย์ผิดหรือโดนจำกัดอัตรา)
- **ประวัติเวอร์ชัน:** เซิร์ฟเวอร์เก็บข้อความก่อนเขียนทับทุกครั้ง; `restoreVersion()` ถาม `ask()` ถ้ามีการแก้ค้าง แล้ว `POST /api/admin/chapters/:id/restore/:version` ฉบับที่ถูกแทนที่ยังอยู่ในประวัติ
- **ทำทีละหลายตอน:** ติ๊กเลือก (จำข้ามหน้า) → `bulkPublish()` เผยแพร่/ซ่อน (`PATCH /api/admin/stories/:id/chapters`)
- **ตรวจความต่อเนื่อง:** `runCheck()` (`POST .../check`) รายงานความขัดแย้งกับตัวละครและสรุปตอนก่อนหน้า
- **ต้องมีคีย์ AI ของตัวเอง:** ถ้าไม่มีจะมีแบนเนอร์ ปุ่ม AI ใช้ไม่ได้ (เว็บไม่มีคีย์กลาง)

### `/admin/users` จัดการผู้ใช้ — `AdminUsers.vue` (แอดมิน)
- **ข้อมูล:** `GET /api/admin/users?page&size&q&role` (พร้อมจำนวนต่อบทบาทสำหรับชิป) และ `GET /api/admin/audit` (ประวัติการเปลี่ยนสิทธิ์/ระงับ/ลบความคิดเห็นของคนอื่น)
- **ฟังก์ชัน:** `choose()` เปลี่ยนบทบาท: เป็นผู้อ่านหรือนักเขียนมีผลทันที เป็นแอดมินต้องยืนยันผ่าน Modal ก่อน (`pending`); เปลี่ยนบทบาทตัวเองไม่ได้; `setSuspended()` ระงับ (ถามก่อน เพราะทำให้ผู้ใช้หลุดทันที) หรือเลิกระงับ (ทันที) ระงับแอดมินไม่ได้ ทุกการเปลี่ยนเขียนลง `audit_log`

### `/admin/reports` รายงานความคิดเห็น — `AdminReports.vue` (แอดมิน)
- **ข้อมูล:** `GET /api/admin/reports` (ความคิดเห็นที่ถูกรายงานพร้อมรายชื่อผู้รายงานและเหตุผล) จำนวนที่ค้างแสดงเป็นเลขบนเมนู "รายงาน"
- **ฟังก์ชัน:** `dismiss()` "ไม่มีปัญหา" (`POST /api/admin/reports/:id/dismiss`); `remove()` ลบความคิดเห็นหลัง `ask()` (ถูกบันทึกในประวัติหน้า "ผู้ใช้")

### `/admin/site` ตั้งค่าเว็บไซต์ — `AdminSite.vue` (แอดมิน)
- **ข้อมูลติดต่อ:** `saveSettings()` (`PUT /api/admin/site`) ชื่อผู้ให้บริการและอีเมลติดต่อ แทนที่ `{{operator}}` / `{{contactEmail}}` ในหน้าข้อมูลทุกหน้า; ยังไม่ตั้งอีเมลจะมีคำเตือน
- **แก้หน้าข้อมูล:** `open(slug)` เปิด Modal แท็บ เขียน (ตัวแก้ไขภาพ) / Markdown / ตัวอย่าง / ประวัติ; `save()` (`PUT /api/admin/pages/:slug`); `resetToDefault()` ใช้ข้อความตั้งต้น (`DELETE`) หลัง `ask()`; `useRevision()` นำเวอร์ชันเก่ามาใส่ตัวแก้ไข (ยังไม่บันทึก); `close()` ถามถ้ามีการแก้ที่ยังไม่บันทึก

## มุมมองจำลองของแอดมิน
เมนูบัญชี → "ดูเป็นนักเขียน / ดูเป็นผู้อ่าน" (เฉพาะแอดมินที่เห็น) → แถบมุมล่างซ้ายบอกสถานะและปุ่ม "ออก" ระหว่างนี้หน้าเว็บเปลี่ยนเมนูและสิทธิ์ตามบทบาทที่เลือก แต่**อ่านอย่างเดียว**: `guardedFetch` ปฏิเสธทุกคำขอที่ไม่ใช่ GET ยกเว้นออกจากระบบ (รวมการเรียก AI และการนับยอดอ่าน) ข้อมูลที่ได้จากเซิร์ฟเวอร์ยังเป็นของแอดมิน
