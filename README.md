# AI Novel

เว็บอ่านนิยายที่ให้ AI แต่ง (ผ่าน [OpenRouter](https://openrouter.ai)) ไว้อ่านส่วนตัว มีทั้งหน้าอ่านสำหรับผู้อ่านและหลังบ้านสำหรับผู้ดูแล

**สำหรับผู้อ่าน:** ชั้นหนังสือ ปกเรื่อง (อัปโหลดเองหรือสร้างอัตโนมัติ) สารบัญ ตัวละครของเรื่อง หน้าอ่านที่ปรับธีม/ฟอนต์/ขนาดตัวอักษรได้ เลือกตอนได้จากในหน้าอ่าน ดาวน์โหลดทั้งเรื่องเป็นไฟล์ EPUB ได้ (เฉพาะตอนที่เผยแพร่) และถ้าเข้าสู่ระบบ ระบบจำตอนที่อ่านค้างไว้ข้ามอุปกรณ์ ฟังเสียงอ่านภาษาไทยได้ (ใช้เสียงของเบราว์เซอร์ ต้องมีเสียงไทยในเครื่อง) และติดตามตอนใหม่ผ่าน RSS (ปุ่ม RSS ที่หน้าเรื่องคัดลอกลิงก์ feed)

หน้าแรกค้นหา/เรียงลำดับได้ มีป้าย "จบแล้ว" / "อัปเดตใหม่" และ "ชั้นหนังสือของฉัน" (ปุ่มติดตามเรื่อง สำหรับผู้ที่เข้าสู่ระบบ) หน้าอ่านจำตำแหน่งที่อ่านค้างในตอน (ซิงก์ข้ามอุปกรณ์เมื่อล็อกอิน) ทำเครื่องหมายตอนที่อ่านแล้วในสารบัญ ซ่อนแถบด้านบนตอนเลื่อนอ่าน ปัดซ้าย/ขวาเปลี่ยนตอนบนมือถือ ปรับความกว้างและระยะห่างบรรทัดได้ และฟอนต์ทั้งหมดอยู่ในตัวเว็บเอง (ไม่เรียก Google Fonts)

**สำหรับผู้ดูแล (admin):** สร้างเรื่อง ให้ AI เขียนตอนใหม่แบบเห็นข้อความไหลสด ตัวแก้ไขตอนแบบ WYSIWYG (แทรกรูป ปรับขนาด/จัดวาง/คำบรรยาย) สรุปตอนอัตโนมัติ จัดการตัวละคร (ให้ AI เสนอจากเรื่องได้) เผยแพร่/ซ่อนตอน ดูค่าใช้จ่าย (tokens / USD) ต่อตอนและรวมทั้งเรื่อง ตั้งเพดานงบรายเดือน ประวัติเวอร์ชันของตอน (กู้คืนฉบับก่อนแก้/ก่อนเขียนใหม่ได้) ตั้งเวลาเผยแพร่ตอน แผนเรื่อง (ให้ AI เขียนตามแผนทีละตอนหรือหลายตอนติดกัน) ปุ่มตรวจความต่อเนื่องของตอน ค้นหานิยายตามชื่อ สถิติการอ่านต่อตอน (ดูหัวข้อ "ข้อควรรู้") จัดการผู้ใช้
**นักเขียน (writer):** admin เป็นคนให้สิทธิ์เท่านั้น (หน้า "ผู้ใช้") เขียนและจัดการได้เฉพาะเรื่องที่ตัวเองสร้าง ดูผู้ใช้/งบรวมไม่ได้ การเปลี่ยนสิทธิ์ทุกครั้งถูกบันทึกในตาราง `audit_log` และแสดงในหน้าเดียวกัน ทุกคนแก้ชื่อ/แนะนำตัว/รหัสผ่านที่ `/profile` ส่วนหน้าผู้แต่งอยู่ที่ `/author/:id`
**เรื่องที่ติดตาม:** หน้า `/following` (เมนู "บัญชี") รวมเรื่องที่กดติดตามไว้ พร้อมความคืบหน้าการอ่าน (อ่านแล้วกี่ตอน มีตอนที่ยังไม่อ่านกี่ตอน ปุ่มอ่านต่อ) กรอง/เรียงลำดับได้ เลิกติดตามทีละเรื่องหรือเลือกหลายเรื่องพร้อมกันได้
**ชุมชนผู้อ่าน:** ทุกคนอ่านได้ ต้องล็อกอินถึงเขียนได้ หน้าสารบัญมี "รีวิวจากผู้อ่าน" (ให้ 1–5 ดาว + ข้อความไม่บังคับ คนละ 1 รีวิวต่อเรื่อง แก้ไขได้ ผู้แต่งรีวิวเรื่องตัวเองไม่ได้ ลบได้เฉพาะเจ้าของรีวิวกับ admin) ส่วนหน้าอ่านแต่ละตอนมีคอมเมนต์ ตอบกลับได้ (ลึก 1 ชั้น) โหวตขึ้น/ลงได้ (โหวตของตัวเองไม่ได้) และเลือกเรียงตาม ใหม่ล่าสุด (ค่าเริ่มต้น) / ยอดนิยม / ตอบกลับมากสุด (ลบได้โดยเจ้าของคอมเมนต์ ผู้แต่งเรื่อง และ admin การลบคอมเมนต์หลักจะลบการตอบกลับใต้มันด้วย) ซึ่งพับไว้เป็นค่าเริ่มต้นเพื่อไม่ให้หน้าอ่านยาวขึ้น
**แจ้งเตือน (กระดิ่งบนหัวเว็บ):** บอกเมื่อ (1) เรื่องที่ติดตามมีตอนใหม่ที่ยังไม่ได้อ่าน (2) มีคนตอบกลับคอมเมนต์ของคุณ (3) คอมเมนต์ของคุณได้โหวตขึ้น (โหวตลงไม่แจ้ง และไม่บอกว่าใครโหวต) ตอนใหม่นับจาก `chapters.released_at` คือเวลาที่ตอนขึ้นให้ผู้อ่านเห็นจริง: ตอนที่ตั้งเวลาไว้ (drip release) จะแจ้งตอนเวลามาถึงเท่านั้น และฉบับร่างเก่าที่เพิ่งกดเผยแพร่ก็นับเป็นตอนใหม่ (ไม่ใช้ `created_at`) รายการตอนใหม่คำนวณสดไม่ได้เก็บเป็นแถว จึงไม่ต้องมีตัวตั้งเวลา และหายไปเองเมื่ออ่านตอนนั้นแล้ว ตัวเลขบนกระดิ่งอัปเดตทุก 1 นาที
**คอมเมนต์:** เจ้าของแก้ไขข้อความตัวเองได้ (ขึ้น "แก้ไขแล้ว") ทุกคนกด "รายงาน" ความคิดเห็นของคนอื่นได้ admin ดู/ปิดรายงานหรือลบความคิดเห็นที่ `/admin/reports` (ป้ายตัวเลขที่แท็บ "รายงาน") การลบความคิดเห็นของคนอื่นโดย admin หรือผู้แต่งเรื่องถูกบันทึกใน `audit_log` ด้วย
**คะแนนรีวิว:** แสดงเป็น "★ 4.3 (12)" ใต้ปกที่หน้าแรกและหน้าผู้แต่ง และเรียง "คะแนน" ได้ (ถ่วงค่าเฉลี่ยกับจำนวนรีวิว เพื่อไม่ให้เรื่องที่มีรีวิวเดียว 5 ดาวชนะเรื่องที่มีรีวิวดี ๆ หลายสิบ) หน้าสารบัญแสดงจำนวนคอมเมนต์ข้างแต่ละตอน

## โครงสร้าง

```
server/   Elysia (Bun) + Drizzle + PostgreSQL   พอร์ต 3000
web/      Vue 3 + Vite + Tailwind CSS           พอร์ต 5173 (proxy /api ไป server)
```

โปรเจกต์เป็น Bun workspace (`package.json` ที่ราก) หน้าเว็บ import ชนิดข้อมูลของ API จาก `server/src` โดยตรง (Eden Treaty) จึงต้องอยู่ repo เดียวกัน

## เริ่มใช้งาน

ต้องมี [Bun](https://bun.sh) และ Docker

```bash
# 1) ฐานข้อมูล
docker compose up -d

# 2) ติดตั้ง dependency (รันที่โฟลเดอร์รากเท่านั้น)
bun install

# 3) ตั้งค่า
cp server/.env.example server/.env
#    แก้ server/.env: ใส่ OPENROUTER_API_KEY, เปลี่ยน JWT_SECRET และ ADMIN_PASSWORD

# 4) สร้างตารางในฐานข้อมูล (รันซ้ำได้ ใช้อัปเดตฐานข้อมูลเดิมด้วย)
cd server && bun run db:migrate

# 5) รัน (เปิดสองเทอร์มินัล)
cd server && bun run dev      # API
cd web && bun run dev         # หน้าเว็บ → http://localhost:5173
```

เข้าสู่ระบบ admin ด้วย `ADMIN_EMAIL` / `ADMIN_PASSWORD` ใน `server/.env` (ระบบสร้างบัญชีนี้ให้ตอนเริ่มครั้งแรกถ้ายังไม่มี) ผู้อ่านสมัครสมาชิกเองได้จากหน้าเว็บ

## ตัวแปรใน `server/.env`

| ตัวแปร | ความหมาย |
|---|---|
| `DATABASE_URL` | ที่อยู่ PostgreSQL (ค่าในตัวอย่างตรงกับ `docker-compose.yml`) |
| `OPENROUTER_API_KEY` | key จาก OpenRouter (โมเดลที่ไม่ใช่ `:free` ต้องเติมเครดิตก่อน) |
| `DEFAULT_MODEL` | โมเดลเริ่มต้น เปลี่ยนรายเรื่องได้ในหน้าตั้งค่าเรื่อง |
| `JWT_SECRET` | ความลับสำหรับ session ใช้ค่าสุ่มยาวๆ เช่น `openssl rand -hex 32` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | บัญชี admin ตั้งต้น **ต้องเปลี่ยนก่อนใช้งานจริง** |
| `MAX_OUTPUT_TOKENS` | เพดานความยาวที่ AI เขียนต่อหนึ่งตอน (กันโมเดลที่วนซ้ำกินเงิน) |
| `UPLOAD_DIR` | ที่เก็บรูปที่อัปโหลด เว้นว่าง = `server/uploads` |
| `NODE_ENV` | ตั้งเป็น `production` ตอน deploy: cookie เป็น `secure`, CORS ปิด (same-origin) และ server ไม่ยอมเริ่มถ้า `JWT_SECRET` สั้นกว่า 32 ตัวอักษร / ยังเป็น `change-me` หรือ `ADMIN_PASSWORD` ยังเป็นค่าตัวอย่าง |
| `CORS_ORIGIN` | origin ของหน้าเว็บ (คั่นด้วย `,`) ใช้เฉพาะเมื่อหน้าเว็บกับ API อยู่คนละโดเมน |
| `ALLOW_REGISTRATION` | `false` = ปิดรับสมัครสมาชิก (ค่าเริ่มต้นเปิด) |
| `MONTHLY_BUDGET_USD` | เพดานค่า AI ต่อเดือน (USD) นับจากค่าที่ระบบบันทึกของตอนที่เขียนเดือนนี้ เกินแล้วระบบไม่ยอมเขียน/เขียนใหม่/ตรวจความต่อเนื่อง เว้นว่าง = ไม่จำกัด |
| `CHECK_MODEL` | โมเดลที่ใช้ตรวจความต่อเนื่อง เว้นว่าง = ใช้โมเดลของเรื่อง (ใช้โมเดลถูกๆ ได้) |
| `SUMMARY_MODEL` | โมเดลที่ใช้สรุปตอน เว้นว่าง = ใช้โมเดลของเรื่อง (ใช้โมเดลถูกหรือโมเดลในเครื่องได้) |
| `LOCAL_BASE_URL` | ที่อยู่เซิร์ฟเวอร์ที่เข้ากับ OpenAI สำหรับโมเดลที่ขึ้นต้น `local:` เว้นว่าง = Ollama ในเครื่อง (`http://localhost:11434/v1`) |
| `LOCAL_API_KEY` | key ของเซิร์ฟเวอร์นั้น (Ollama ไม่ต้องใช้) |
| `PUBLIC_URL` | URL จริงของหน้าเว็บ (เช่น `https://novel.example.com`) ใช้สร้างลิงก์ใน RSS feed ถ้าเว้นว่างจะใช้ host ที่ server เห็น ซึ่งผิดเมื่ออยู่หลัง proxy หรือตอนรันด้วย Vite |

## ข้อควรรู้

- **รูปที่อัปโหลด** อยู่ในโฟลเดอร์ `server/uploads` (ไม่อยู่ใน git) ถ้า deploy ต้องผูก volume ถาวรไว้ ไม่งั้นรูปหายเมื่อสร้างเครื่องใหม่
- **ค่าใช้จ่าย** คิดตามที่ OpenRouter เรียกเก็บ ประมาณ 0.4-6 บาทต่อตอน ขึ้นกับโมเดล (ตอนยาว 2,000-3,000 คำ)
- **ค่าใช้จ่ายที่แสดงในหน้า admin** มาจากตัวเลขที่ OpenRouter รายงานกลับมา รวมค่าเขียนตอนและค่าสรุป ตอนที่เขียนก่อนมีฟีเจอร์นี้ หรือที่กดหยุดกลางคัน/โมเดลวนซ้ำ จะไม่มีตัวเลข (ไม่นับรวม) และ "เขียนใหม่" กับ "เสนอตัวละคร" ไม่ถูกนับ
- **สถิติการอ่านเป็นตัวเลขรวมแบบไม่ระบุตัวตน** ระบบนับเฉพาะ "จำนวนครั้งที่เปิดตอน" และ "จำนวนครั้งที่อ่านจนจบ" ต่อตอน (เบราว์เซอร์ส่งไม่เกินวันละครั้งต่อตอน) ไม่เก็บว่าใครอ่านและไม่เก็บ IP (ใช้ IP แค่ในหน่วยความจำเพื่อจำกัดอัตราการส่ง) ตัวเลขอาจเกินจริงจากบอตหรือการล้างข้อมูลเบราว์เซอร์
- **ตำแหน่งที่อ่านค้างและเครื่องหมายอ่านแล้ว** ผู้ที่ล็อกอินเก็บบนบัญชี ผู้ที่ไม่ล็อกอินเก็บในเบราว์เซอร์นั้น (ตอนล่าสุด 50 ตอน) ตอนที่อ่านจบ (เลื่อนเกิน 97%) เปิดใหม่จะเริ่มจากต้นตอน
- **ตั้งเวลาเผยแพร่** ใช้เวลา UTC ของ DB เทียบตอน query (ไม่มี cron) ตอนที่ถึงเวลาจะขึ้นเองโดยไม่ต้องรีสตาร์ต
- **ตรวจความต่อเนื่อง** เป็นแค่คำแนะนำจากโมเดลและเสียค่า AI ต่อครั้ง ผลไม่ถูกบันทึก (บันทึกเฉพาะค่าใช้จ่ายรวมเข้าตอนนั้น)
- **คุณภาพภาษาไทย** ของโมเดลฟรีบางตัวต่ำ (สระหาย วนซ้ำ) แนะนำโมเดลที่เก่งไทยสำหรับเรื่องจริง
- ถ้าติดตั้งแพ็กเกจใหม่แล้ว build ล้มด้วย `The service was stopped` บน macOS ให้ลบแล้วคัดลอกไฟล์ `node_modules/@esbuild/darwin-arm64/bin/esbuild` ใหม่ (ระบบฆ่าไบนารีที่ถูก hardlink)

## รันโมเดลในเครื่อง (Ollama)

ใส่ `local:` นำหน้าชื่อโมเดลในช่อง Model ของเรื่อง (หรือใน `DEFAULT_MODEL` / `SUMMARY_MODEL` / `CHECK_MODEL`) ระบบจะส่งไป Ollama แทน OpenRouter ชื่อที่ไม่มี `local:` ไปทาง OpenRouter เหมือนเดิม จึงผสมกันได้ เช่น เขียนเรื่องด้วยโมเดลคลาวด์ แต่สรุปตอนด้วยโมเดลในเครื่อง

```bash
winget install Ollama.Ollama
ollama pull gemma4:12b                        # รุ่น 12B (ใส่ GPU 12 GB ได้ทั้งตัว)
# ตั้งตัวแปรสภาพแวดล้อมของ Ollama แล้วรีสตาร์ต Ollama: OLLAMA_CONTEXT_LENGTH=32768
ollama run gemma4:12b --verbose               # ลองไทย + ดู tokens/วินาที
```

ตัวอย่างค่าในช่อง Model: `local:gemma4:12b`

- **ต้องตั้ง context ให้ใหญ่** ระบบส่งสรุปตอนก่อน + 2 ตอนล่าสุดเต็ม + ตัวละคร (20k+ tokens) ถ้า context เริ่มต้นของ Ollama เล็กกว่านั้น บริบทจะถูกตัดโดยไม่มีข้อความเตือน ตรวจด้วย `ollama ps` ว่า `CONTEXT` ตรงกับที่ตั้ง
- ทดสอบแล้วกับ RTX 5070 (12 GB) + Ollama 0.35.1: `gemma4:12b` ใส่ GPU ได้ทั้งตัวที่ context 32768 (ใช้ VRAM ~10.6 GB) เขียนไทยได้ และจำข้อมูลกลางข้อความยาว 30,000 ตัวอักษรได้ ส่วน `scb10x/typhoon2.1-gemma3-12b` โหลดไม่ขึ้นกับ Ollama รุ่นนี้ (template ในไฟล์โมเดลถูกปฏิเสธ: `selectattr: unknown test 'tool_calls'`) จึงยังไม่ได้ใช้
- โมเดลในเครื่องไม่รายงาน `cost` หน้า admin จึงแสดงค่าใช้จ่าย $0 (มี tokens)
- ต้องเปิด Ollama ค้างไว้ตอนใช้งาน ถ้าเชื่อมต่อไม่ได้ ระบบแจ้งเป็นข้อความในหน้าเขียนตอน

## คำสั่งที่ใช้บ่อย

```bash
cd web && bunx vue-tsc --noEmit -p tsconfig.app.json   # ตรวจชนิดข้อมูลหน้าเว็บ (รวมชนิดของ API)
cd server && bunx tsc --noEmit                         # ตรวจชนิดข้อมูล server
cd server && bun test                                  # เทสต์ (อยู่ใน server/test)
cd web && bun test                                     # เทสต์ฝั่งเว็บ (web/test)
cd server && bun run db:generate                       # หลังแก้ schema.ts: สร้างไฟล์ migration ใหม่ใน server/drizzle
cd web && bunx vite build                              # build หน้าเว็บ
```
